## Этап A — исправления в коде (выполнен 2026-11-08, версия 0.2.2)

1. **keep-config (#1).** `uninstall.sh --keep-config` записывает `status: "uninstalled"`. `hvk_validate_state` принимает этот статус. `install.sh` при `uninstalled` автоматически переходит в режим `--repair` (секреты и клиенты сохраняются). `update.sh` отказывается работать при `uninstalled` или отсутствующем core и подсказывает `install.sh --repair`; `install.sh` при `ready`, но без core, подсказывает `--repair`.
2. **uninstall при битом state (#2, #12).** Значения читаются с умолчаниями без падения; ufw-правило удаляется только при валидном порте и записанном владении. Разбор аргументов и `--help` — до проверки root и блокировки.
3. **ufw (#3, #12).** Одна функция `hvk_ufw_udp_rule PORT` → `allow|deny|none` по первому подходящему правилу (`PORT/udp`, `PORT`, диапазоны `A:B`, списки `a,b`, `(v6)`, `ALLOW/LIMIT/DENY/REJECT`, только `From = Anywhere`, без правил `OUT`). Установщик: `none` → добавить правило, `allow` → ничего, `deny` → предупреждение без изменения правил. `doctor`: различает «нет правила» и «запрещено правилом».
4. **sysctl (#4, #12).** Значение = max(7 500 000, текущее значение ядра, значения из других sysctl-файлов). `hvk_sysctl_file_valid` проверяет `>=`. `doctor` использует `$HVK_SYSCTL`.
5. **Права (#5).** `hvk_validate_state` проверяет читаемость и сообщает «cannot read …: run as root».
6. **Внешний IP (#7).** Несколько сервисов по очереди (`api.ipify.org`, `ifconfig.me`, `icanhazip.com`, `ident.me`), затем `src` из `ip route`, если адрес публичный.
7. **Секреты (#9, #10).** Пароли генерируются в переменную, проверяется длина, в `jq` передаются через окружение (`$ENV`). `hvk_rand` ограничен числом попыток.
8. **update.sh (#11).** Сначала скачивание и проверка core, затем бэкап; временный каталог удаляется при любом исходе.
9. Тесты на всё перечисленное, README, `VERSION` → 0.2.2, `STATUS.md`, `TODO.md`.

## Этап B — проверка на ВМ (выполнено частично 2026-11-08)

Итог: пункт 6 подтверждён на реальном ядре 2.13.0 (`FATAL ... auth.userpass: empty auth userpass`). Решение: без клиентов сервис остаётся остановленным (`hvk_restart_service` делает `stop`), `hy2-client add` запускает его, `doctor` показывает WARN вместо FAIL, `remove` последнего клиента останавливает сервис и сообщает об этом. Сценарий install без клиентов → add → remove → add → `uninstall --keep-config` → `install` (секреты сохранены) → `doctor` (13 ok) прошёл на Debian 13 ВМ. Реальный ufw на ВМ выключен: логика правил проверена только на имитированном выводе. Невыполнено: п. 3 (реальный ufw) и п. 4 (CI-проверка конфига настоящим ядром).

Исходный план этапа:

1. На Debian 13 ВМ (`localnet`): `bash tests/lint.sh`, `bash tests/run.sh`.
2. Реальный core 2.13.0: проверить #6 — старт с пустым `userpass`. Если не стартует: запретить `remove` последнего клиента (без `--force`, который останавливает сервис осознанно) и `--no-first-client` при реальной установке.
3. Реальный ufw: правила `PORT/udp`, `PORT`, `DENY`, диапазон.
4. CI-шаг: скачать закреплённый core и проверить, что он принимает отрендеренные конфиги (с obfs/без).
